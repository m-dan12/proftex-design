## 1. Цель и контекст

Нужен веб-сервис `design.proftex.tech`, через который дизайнеры генерируют и точечно правят изображения моделью OpenAI (GPT Image 2.5 Sunburst и другими), а ключ API остаётся на сервере; администратор видит, кто и сколько потратил.

**Зачем.** Модель `gpt-image-2.5-sunburst` доступна только через API: в обычном интерфейсе ChatGPT её не выбрать. Рабочий сценарий дизайнеров: загрузить фото интерьера и принт ткани, затем много раз просить «ничего не менять, только уменьшить рюши / перенести принт / убрать предмет».

**Пользователи.** Дизайнеры (около 5–10 человек, число уточняется) и администратор.

**Что считается успехом:**

- Дизайнер входит под своим логином и получает результат с несколькими референсами и промптом в один абзац.
- Результат одним кликом становится исходником для следующей правки.
- Работы видны в личной и в общей галерее.
- Администратор и сам дизайнер видят потраченную сумму по людям, моделям и дням.
- Сервис работает по HTTPS и не мешает монитору `ops.proftex.tech` на том же VDS.

**Вне объёма первой версии:** лимиты и квоты, самостоятельная регистрация, показ реального остатка на счёте OpenAI (публичного API для него нет), редактор с маской и кистью (первый кандидат на версию 1.1: для точечных правок он нужнее всего остального), оплата, мобильное приложение.

**Допущения (не проверены):**

- Модель `gpt-image-2.5-sunburst` существует и принимает несколько изображений в `images.edit`. Страница документации отдаёт 403, проверим первым реальным вызовом.
- Цены в `models.json` ориентировочные и проверяются по таблице цен на platform.openai.com. У моделей-картинок три разные цены: текстовые входные токены, картиночные входные токены и выходные токены; API отдаёт их раздельно (`usage.input_tokens_details`).
- Модель поддерживает `input_fidelity`, `n` и `output_format`; если какой-то параметр не поддерживается, он выключается для модели в `models.json`.
- Правка «цепочкой» делается через `images.edit`, когда предыдущий результат передаётся как референс; Responses API с диалоговым контекстом — позже, если понадобится.
- Остаток баланса OpenAI через API получить нельзя: «балансом» для дизайнеров считается сумма, потраченная через сервис.
- Дизайнеры пользуются сервисом с ноутбука или ПК, ширина экрана от 360 px.

## 3. Функциональные требования

Система делится на шесть модулей, у каждого требования есть номер FR-…, на который ссылаются задачи и приёмка.

| № | Модуль | Требование |
| --- | --- | --- |
| FR-01 | Вход | Вход по логину и паролю, сессия в cookie на 30 дней, выход. |
| FR-02 | Вход | Администратор создаёт пользователя, сбрасывает пароль, блокирует и разблокирует; пользователь меняет свой пароль. |
| FR-03 | Генерация | Форма: промпт (до 4000 символов), модель, качество, размер, точность к референсам `input_fidelity` (`low`/`high`, если модель поддерживает; по умолчанию `high`), число вариантов 1–4, формат результата (JPEG, PNG, WebP из списка модели; по умолчанию JPEG), референсы: 0–10 файлов (PNG, JPEG, WebP, до 20 МБ каждый) или прошлые работы из галереи. |
| FR-03a | Генерация | Запуск с N вариантами создаёт N работ с общим `batch_id` и номерами `variant_idx`; в галерее каждый вариант — отдельная работа, на экране генерации варианты показываются рядом. Стоимость одного запроса делится между вариантами поровну, остаток микродолларов — первому. |
| FR-04 | Генерация | Запуск фоновый: статус `pending` → `running` → `done` или `error`; страница не блокируется, можно запустить несколько подряд. |
| FR-05 | Генерация | Ошибки OpenAI (модерация, лимиты, таймаут) показываются понятным текстом; расход по неудачной генерации равен 0. |
| FR-06 | Генерация | «Править дальше»: результат становится референсом новой генерации, в базе сохраняется `parent_id`. |
| FR-07 | Генерация | «Повторить»: форма заполняется промптом и настройками прошлой работы. |
| FR-08 | Галереи | Две вкладки: «Мои» и «Общая»; сетка превью, подгрузка по мере прокрутки, в общей фильтр по автору. |
| FR-09 | Галереи | Карточка работы: результат, референсы, промпт, модель, качество, размер, стоимость, автор, время; скачивание файла в формате результата. |
| FR-10 | Галереи | Переключатель «Видна всем» (по умолчанию включён); приватные работы видят только автор и администратор. |
| FR-11 | Галереи | Удаление своей работы; администратор удаляет любую. |
| FR-12 | Расходы | Каждая завершённая генерация сохраняет токены раздельно (текст на входе, картинки на входе, выход) и стоимость в USD. |
| FR-13 | Расходы | «Мои расходы»: итог за период, разбивка по дням и моделям. |
| FR-14 | Расходы | Администратор: расходы по пользователям, моделям, дням, фильтр по периоду, выгрузка CSV. |
| FR-15 | Модели | Список моделей, качеств, размеров, форматов, поддержки `input_fidelity` и `n`, и три цены (`text_in`, `image_in`, `image_out` за млн токенов) плюс запасная цена за картинку лежат в `models.json` и меняются перезапуском без пересборки. |
| FR-16 | Эксплуатация | `GET /api/health` (статус, режим, свободное место на томе в процентах); логи без ключей и паролей. |
| FR-18 | Эксплуатация | Аварийный потолок: если сумма расходов всех пользователей за текущие сутки (Europe/Moscow) достигла `SPEND_CAP_DAILY_USD`, новые генерации отклоняются с 429 и текстом «дневной бюджет сервиса исчерпан, обратитесь к администратору». Пустое значение — потолка нет. |
| FR-19 | Вход | Сброс пароля администратором — отдельная операция `POST /api/admin/users/{id}/reset-password`: сервер генерирует пароль из 12 символов и возвращает его в ответе один раз; в базе только хэш. |
| FR-17 | Эксплуатация | Режим заглушки: без `OPENAI_API_KEY` сервис рисует тестовые картинки и считает фиктивные токены, в интерфейсе видна пометка «тестовый режим». |

## 4. Нефункциональные требования

Каждое требование измеримо, поэтому его можно проверить командой или тестом.

| № | Категория | Требование |
| --- | --- | --- |
| NFR-01 | Безопасность | Пароли хранятся только в виде хэша scrypt; cookie `HttpOnly`, `Secure`, `SameSite=Lax`. |
| NFR-02 | Безопасность | Ключ OpenAI живёт только в `.env` на сервере (права 600); ни в ответах API, ни в логах, ни в git. |
| NFR-03 | Безопасность | Не более 5 неудачных попыток входа в минуту с одного IP, дальше ответ 429. IP клиента берётся из `X-Forwarded-For` только если запрос пришёл от доверенного прокси (`TRUSTED_PROXIES`, по умолчанию адрес Caddy в Docker-сети); иначе — адрес соединения. Без этого все пользователи за Caddy выглядят одним IP и блокируют друг друга. |
| NFR-04 | Безопасность | Загружаемые файлы проверяются по содержимому (открываются как изображение), а не по расширению; имена на диске генерирует сервер. Защита от «бомб»: `Image.MAX_IMAGE_PIXELS` = 4096×4096, превышение → 422; файлы пишутся на диск потоком и проверяются по одному, а не все 10 в памяти сразу. |
| NFR-05 | Безопасность | Картинки отдаются только после проверки прав (своя, общая или администратор); прямого доступа к папке с файлами нет. |
| NFR-06 | Производительность | Ответ API (кроме самой генерации) в 95% случаев быстрее 300 мс. |
| NFR-07 | Производительность | Галерея из 50 работ грузится не дольше 1,5 с; превью WebP шириной 400 px весят не больше 60 КБ. |
| NFR-08 | Производительность | Одновременно в OpenAI уходит не более 4 запросов, остальные ждут в очереди в статусе `pending`. Очередь работает в одном процессе: Uvicorn запускается строго с `--workers 1`, это записано в Dockerfile и README. |
| NFR-09 | Надёжность | Перезапуск контейнера не теряет данные и картинки; задачи, оставшиеся в `pending`/`running`, при старте получают `error` с пояснением. |
| NFR-10 | Надёжность | Таймаут запроса к OpenAI 300 с, один повтор при 429 и 5xx. |
| NFR-11 | Бэкап | База попадает в ежедневный бэкап VDS через хук в `/opt/backup/pre.d/` (копия `sqlite3 .backup`); папки `results/` и `inputs/` копируются раз в неделю (инкрементально, `rsync` в каталог бэкапа; `thumbs/` не нужны, они пересоздаются); восстановление проверено на тестовой копии. |
| NFR-15 | Надёжность | Место на диске: `/api/health` отдаёт `disk_free_pct`; при значении ниже 10% статус `degraded`, а монитор `ops.proftex.tech` (если умеет проверять JSON) или cron-скрипт пишет предупреждение администратору. |
| NFR-12 | Сосуществование | Деплой не ломает `ops.proftex.tech`: перед изменением Caddy делается копия конфига и `caddy validate`. |
| NFR-13 | Совместимость | Последние две версии Chrome, Edge, Firefox, Safari; ширина от 360 px без горизонтальной прокрутки страницы. |
| NFR-14 | Качество кода | `pytest` без ошибок, покрытие сервисного слоя не ниже 80%, `ruff` и `vue-tsc` без ошибок, README с запуском и деплоем. |

## 5. Архитектура

Браузер говорит только с нашим бэкендом, бэкенд — с OpenAI; всё данные лежат в одном Docker-томе, а наружу сервис выходит через уже работающий Caddy.

**Компоненты**

| Компонент | Роль |
| --- | --- |
| Caddy (уже на VDS) | HTTPS, сертификаты, проксирование `design.proftex.tech` на контейнер `design-studio`; `ops.proftex.tech` не трогаем |
| Контейнер `design-studio` | FastAPI отдаёт API и собранный фронтенд (статика Vue); в нём же фоновый исполнитель генераций с очередью на 4 потока; ровно один процесс Uvicorn (`--workers 1`) |
| Том `design-data` | `app.db` (SQLite) + папки `results/`, `thumbs/`, `inputs/` |
| Слой `provider` | один интерфейс «промпт + референсы → картинка + токены», две реализации: OpenAI и заглушка |
| Слой `pricing` | читает `models.json`, считает стоимость по трём видам токенов (`text_in`, `image_in`, `image_out`) или по цене за картинку, если API не вернул usage |

**Модель данных**

| Таблица | Ключевые поля |
| --- | --- |
| `users` | `id`, `username` (уникальный), `password_hash`, `is_admin`, `is_active`, `daily_limit_micro_usd` (пусто = без лимита, в v1 не проверяется), `created_at` |
| `generations` | `id`, `user_id`, `parent_id`, `batch_id`, `variant_idx`, `model`, `quality`, `size`, `input_fidelity`, `output_format`, `prompt`, `status`, `error`, `shared` (по умолчанию 1), `input_text_tokens`, `input_image_tokens`, `output_tokens`, `cost_micro_usd`, `result_path`, `thumb_path`, `created_at`, `finished_at` |
| `generation_inputs` | `id`, `generation_id`, `idx`, `path`, `source_generation_id` (если референс — прошлая работа), `filename` |

**API** (единственный источник правды — `contracts/openapi.yaml`, пишется в задаче T01 и после неё не меняется)

| Запрос | Назначение | Кто может |
| --- | --- | --- |
| `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/me`, `POST /api/me/password` | вход, выход, профиль, смена пароля | все / авторизованные |
| `GET /api/models` | модели, качества, размеры | авторизованные |
| `POST /api/generations` (multipart) | создать задачу на 1–4 варианта, ответ 202 с `batch_id` и списком `ids`; 429 при исчерпанном дневном потолке | авторизованные |
| `GET /api/generations?scope=mine\|shared&cursor=` | список для галереи | авторизованные |
| `GET/PATCH/DELETE /api/generations/{id}` | карточка, флаг `shared`, удаление | автор и администратор (чтение общих — все) |
| `GET /api/generations/{id}/image?kind=result\|thumb\|input&idx=` | файл с проверкой прав | по правам работы |
| `GET /api/spending/me?from=&to=` | мои расходы | авторизованные |
| `GET /api/admin/spending?from=&to=&group=user\|model\|day`, `GET /api/admin/spending.csv` | расходы всех | администратор |
| `GET/POST /api/admin/users`, `PATCH /api/admin/users/{id}` | список, создание, блокировка и разблокировка, `daily_limit_micro_usd` | администратор |
| `POST /api/admin/users/{id}/reset-password` | сброс пароля, ответ `{"password": "..."}` один раз | администратор |
| `GET /api/health` | живость, режим (`mock`/`openai`), `disk_free_pct` | все |

## 6. Показатели готовности системы в целом

Система готова, когда зелёными становятся все показатели S-01…S-16 в заглушечном режиме на `design.proftex.tech`; S-17 запускается, когда появится ключ OpenAI, и нужен для финальной сдачи. Каждый показатель имеет порог и способ проверки.

| № | Показатель | Порог готовности | Как проверить |
| --- | --- | --- | --- |
| S-01 | Доступность | `https://design.proftex.tech/api/health` отвечает 200; сертификат действует ещё не менее 14 дней; `http://` перенаправляет на `https://` | `curl -sI`, `openssl s_client` |
| S-02 | Соседний сервис | `ops.proftex.tech` отвечает тем же кодом, что до деплоя (код записывается до) | `curl -s -o /dev/null -w '%{http_code}'` до и после |
| S-03 | Вход и роли | верный пароль → 200 и cookie с `HttpOnly; Secure; SameSite=Lax`; неверный → 401; 6-я попытка за минуту с одного IP → 429, а другой пользователь с другого IP за тем же Caddy входит без помех; заблокированный → 403; обычный пользователь на `/api/admin/*` → 403 | e2e-сценарий + `curl -i` |
| S-04 | Генерация без референсов | в заглушечном режиме статус `done` ≤ 15 с, файл открывается в выбранном формате, размер совпадает с выбранным; запуск с `n=3` даёт 3 работы с общим `batch_id` | e2e + `python -c "PIL..."` |
| S-05 | Генерация с референсами | 3 файла + промпт → `done`; в карточке видны 3 референса | e2e |
| S-06 | Правка цепочкой | из результата A за не более 3 кликов запускается B, `B.parent_id = A`, A лежит в референсах B | e2e + запрос к API |
| S-07 | Параллельность | 6 запусков подряд: одновременно `running` ≤ 4, все заканчиваются `done`, `/api/health` всё время отвечает быстрее 300 мс | скрипт нагрузки `scripts/load_check.py` |
| S-08 | Галереи и приватность | новая работа видна другому пользователю в «Общей»; после выключения «Видна всем» исчезает после обновления, прямой запрос её картинки другим пользователем → 404, администратор видит всё | e2e с двумя пользователями |

## 10. Протокол выполнения задачи

Агент берёт одну задачу, делает её и проверяет себя по её показателям в одном запросе; задача закрыта только тогда, когда все показатели зелёные. Фразы «код написан» и «тесты не запускались» готовностью не считаются.

**Шаги агента**

1. Прочитать карточку задачи, разделы 3–6 и `contracts/openapi.yaml`. Файлы вне своего списка не трогать.
2. Работать в отдельной ветке `task/Txx` (отдельный git worktree), если задачу делают параллельно с другими.
3. Сначала написать тесты по показателям, затем код.
4. Прогнать все команды проверки из карточки и записать результат по каждому показателю.
5. Если хоть один показатель красный, найти причину, исправить и прогнать всю проверку заново, а не только упавшую часть. Доработок не больше трёх кругов.
6. Если после трёх кругов показатель всё ещё красный, задача получает статус «заблокирована». В отчёте: какой показатель, что пробовали, гипотеза причины. Чужие файлы не править.
7. Закоммитить в ветку и отдать отчёт.

**Формат отчёта агента**

| № показателя | Результат | Доказательство (команда и её вывод) |
| --- | --- | --- |
| 1 | зелёный или красный | … |

В отчёте также: число кругов доработки, список изменённых файлов, заявки на правку контракта (если были).

**Правила параллельной работы**

- **Контракт заморожен после T01.** Если нужна правка, агент не правит её сам, а пишет заявку; решение принимает оркестратор (человек или главный агент), правка делается отдельной мини-задачей T01.x, затронутые задачи перепроверяются.
- **Один владелец на файл.** Общие файлы правит только T01, а в интеграции — T15 с записью в отчёте.
- **Слияние по волнам.** Сначала все задачи волны зелёные по своим показателям, затем слияние в `main` по номерам, затем `make check`. Красный `make check` после слияния — дефект интеграции, который возвращается владельцу или чинится в T15.
- **Секреты.** Агент не читает и не печатает значения из `.env`, не просит ключ в чат.
- **Внешние действия.** VDS, reg.ru и ключ OpenAI трогает только T16 (и разведка на чтение в T07), перед изменениями — подтверждение заказчика.

## 12. Риски и открытые вопросы

Главный риск — модель и её цены: до первого реального вызова они не проверены, поэтому весь сервис строится так, чтобы модель менялась одной строкой в `models.json`.

| Риск | Что может случиться | Что делаем |
| --- | --- | --- |
| Модель недоступна или имя другое | S-17 красный, генерации дают ошибку «модель недоступна» | Замена в `models.json`, запасные модели уже в списке |
| Требуется верификация организации в OpenAI или нет баланса | Ключ отдаёт 403 или 402 | До того сервис работает в режиме заглушки; ключ и баланс — на стороне заказчика |
| Цены в `models.json` неверны | Счётчик расходов расходится со счётом OpenAI | Сверка в S-17 (допуск 10%), потом периодическая сверка с Usage |
| Долгая генерация на качестве `max` | Минуты ожидания, зависшие запросы | Фоновая очередь, таймаут 300 с, статус в интерфейсе |
| Модерация OpenAI отклоняет запрос (люди на фото, бренды) | Генерация падает без результата | Понятный текст ошибки, расход 0 (FR-05) |
